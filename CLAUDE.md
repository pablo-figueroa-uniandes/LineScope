# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

LineScope is a native macOS app (SwiftUI with some AppKit, macOS 15+). It compares an image with filtered and resampled copies of it:

- **Zone 1:** image tabs.
- **Zone 2:** a channel profile sampled along a draggable line.
- **Zone 3:** the FFT of that profile.
- **Inspector window:** details about the focused image.

There is also a Windows port in `Windows/` (C# / .NET 9 / WPF); see "Windows port" below. The two code bases are maintained side by side. When you change behavior in one, make the matching change in the other.

## Commands

The Xcode project is generated by XcodeGen from `project.yml`. `LineScope.xcodeproj` is committed so the repo opens in Xcode directly, but don't edit it by hand. Regenerate it, and commit the result, after adding, removing or renaming files:

```sh
xcodegen generate
xcodebuild -project LineScope.xcodeproj -scheme LineScope -configuration Debug -derivedDataPath build build
open build/Build/Products/Debug/LineScope.app            # or: open -a "$PWD/build/Build/Products/Debug/LineScope.app" image.png
```

Core logic tests are SwiftPM/XCTest in the local package:

```sh
cd Packages/LineScopeCore && swift test
swift test --filter SpectrumTests/testSinePeak             # single test
```

### Literate program (`LiterateP/`)

The whole codebase, Swift and C#, is also presented as a noweb-style literate program. `LiterateP/chapters/*.nw` hold LaTeX prose and code chunks: Part I (chapters `10`–`70`) is the macOS code and Part II (`80`–`88`) the Windows port. Root chunks are named by repo path and must tangle to the sources byte for byte.

**After any source change, update the matching chunk and run `make check`.** It fails on any difference or on an uncovered source file.

```sh
cd LiterateP && make check     # tangled web == repository sources
cd LiterateP && make pdf       # LiterateP/linescope.pdf via tectonic (committed)
```

Without `make` (Windows), run `py lit.py check --root .. <the --require globs from the Makefile> chapters/*.nw`. Non-root chunks of Part II are prefixed `Win ` so they don't collide with Part I names.

## Architecture

- **`Packages/LineScopeCore`:** all numeric code, UI-free and unit-tested.
  - `PixelBuffer` is the working format: interleaved RGBA Float32, sRGB-*encoded* (not linearized), straight alpha, row 0 at the top. Resampling and Core Image convert to premultiplied internally.
  - `Resampler` uses explicit separable kernels, not vImage or Core Image, so each menu item is exactly the algorithm it names. `nearest` has no prefilter, so it aliases. The kernel methods widen their support by 1/scale when downscaling:
    - tent (bilinear);
    - Catmull-Rom and Mitchell-Netravali, both from the BC-spline family: (0, ½) and (⅓, ⅓);
    - Lanczos-3;
    - truncated sinc (`sincRadius`).

    Mitchell is approximating rather than interpolating, so it is not an identity at ×1. `area` uses exact footprint coverage.
  - `Filters` wraps Core Image with color management disabled (`workingColorSpace: NSNull`), plus CPU 3×3 kernels.
  - `LineSampler` takes `ceil(pixel length)+1` bilinear samples in each image's *own* grid. `SpectrumAnalyzer` is a vDSP real FFT, zero-padded to a power of two, with single-sided amplitude normalized by the window sum.
  - The package forces `-O` in Debug (`unsafeFlags`) because pixel loops are too slow at `-Onone`.
- **Line sync:** `LineSegment` is stored in normalized image coordinates (0…1). Filters keep the size and resampling only scales it, so one shared line maps onto the same content in every copy.
- **`Session` (`LineScope/Model/Session.swift`):** one `@Observable` per document window. It owns:
  - the variants (index 0 is the original);
  - the line;
  - the color model, channel and spectrum settings, shared by all panes so comparisons match;
  - `panes[zone]` for splitting;
  - `focusedVariantID`, the target of menu operations and what the inspector shows.

  Operations run in `Task.detached` and apply to the focused variant, so they chain. Each variant stores its full `lineage`.
- **Document model:** `DocumentGroup(viewing:)` with a read-only `ImageDocument`. EXIF orientation is intentionally ignored.
- **Test patterns:** `TestPatternGenerator` in the core package makes the synthetic images. Each pattern is described by a `Codable` `TestPatternSpec` (kind, size, one parameter), and the kind carries the parameter's name, default and range. In the app, File ▸ New Test Pattern calls `openWindow(value: spec)`. A `WindowGroup(for: TestPatternSpec.self)` builds an `ImageDocument(pattern:)` and shows it in the same `MainView` as a file. Patterns are deterministic (noise is seeded), so restored windows regenerate identically.
- **Focus plumbing:** menus use `@FocusedValue(\.session)` and fall back to `ActiveSession.shared`. The inspector window only uses `ActiveSession.shared`, which `WindowKeyObserver` in `MainView.swift` updates when a document window becomes key. This is needed because the inspector is itself the key window while you use it.

## Windows port (`Windows/`)

```sh
cd Windows
dotnet build LineScope.sln
dotnet run --project LineScope.App [-- image.png]
dotnet test LineScope.Core.Tests                                          # all core tests
dotnet test LineScope.Core.Tests --filter "FullyQualifiedName~SpectrumTests.SinePeak"
```

- **`LineScope.Core`** (net9.0, no UI dependencies) ports `Packages/LineScopeCore` file by file, with the same names in PascalCase. Keep the algorithms identical: kernels, sampling, spectrum normalization, pattern formulas and SplitMix64.
  - Differences from Swift:
    - `Spectrum.cs` has its own radix-2 FFT in place of vDSP.
    - `Filters.cs` reimplements the Core Image filters on the CPU (Gaussian σ = radius, box, 3×3 median, unsharp mask, threshold-based noise reduction). Their output is therefore not bit-identical to macOS.
    - `PixelBuffer` is a class (treat it as immutable), and its 8-bit bridge is premultiplied BGRA (`Pbgra32`).
  - `Optimize` is on even in Debug, like the Swift package's `-O`.
- **`LineScope.App`** (WPF, views built in C#, no XAML except `App.xaml`):
  - `Session` raises `Changed(SessionChange flags)`, and each view redraws only what the flags cover.
  - Every `MainWindow` has its own menu bar, bound to its own session. `ActiveSession` is set on `Window.Activated` and feeds the Inspector.
  - `ImageDocument` decodes with WIC and converts embedded ICC profiles to sRGB. It ignores EXIF orientation.
  - Charts are drawn with `DrawingContext` in `Views/Charts.cs`.
- `Windows/README.md` documents the mapping from macOS frameworks to Windows, the shortcuts and the known numerical differences. Update it when either side changes.
